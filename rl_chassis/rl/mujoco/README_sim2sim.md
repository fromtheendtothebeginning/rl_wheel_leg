# v11 轮腿策略：接口规格（sim2sim / 单片机移植手册）

本文档说明**策略的输入输出到底是什么**，单位、顺序、缩放、限幅、以及从策略的"虚拟腿"
口径到真机闭链的换算，目标是让你能照着在单片机上复现同一个控制器。

配套文件：

| 文件 | 作用 |
|---|---|
| `onnx_mj_v11.py` | MuJoCo sim2sim，本策略的**黄金参考实现**（真机口径：闭环逆解 + 雅可比映射） |
| `../tools/leg_kinematics_ref.py` | **不依赖 MuJoCo 的纯 numpy 闭链运动学**，单片机照抄这个 |
| `v11_plane_3000.onnx` | 策略网络（38825 参数，152 KB fp32 / 38 KB int8） |

## 1. 信号流总览

```
                            ┌─────────────────────────────────────────┐
 IMU(陀螺+姿态) ───────────▶│ obs[0:6]   角速度、投影重力              │
 编码器 ×6 ────┬───────────▶│ obs[9:13]  髋/膝角偏差  (膝=闭环逆解)    │
               │            │ obs[13:19] 6 个关节角速度               │
               └─闭环逆解─▶ └─────────────────────────────────────────┘
 手柄/上位机 ──────────────▶  obs[6:9]    指令 vx, wz, 高度
 策略上一次输出 ───────────▶  obs[19:25]  上一步动作
                                       │
                     obs(25) + history(125)  ──▶  ONNX  ──▶  actions(6)
                                       │
                          PD 控制器（kp/kd + 动作尺度）
                                       │
                     虚拟 (髋, 膝, 轮) 力矩
                                       │  虚功原理 / 雅可比
                        真机 (后髋=大腿, 前髋=曲柄, 轮) 力矩 ──▶ 6 个电机
```

**控制频率 100 Hz**（训练时 `dt=0.005 s` × `decimation=2`，即每 10 ms 给一次动作）。
训练里没有随机动作延迟（`randomize_action_delay=False`），所以单片机端尽量保持
**固定且尽量小的延迟**。

## 2. 策略本体

| 项 | 值 |
|---|---|
| 结构 | 历史编码器 `125→128→64→3`(ELU) + 动作网络 `(25+3)→128→64→32→6`(ELU) |
| 激活 | ELU：`x>0 ? x : exp(x)-1` |
| 参数 | 38825 个 float32（encoder 24579 + actor 14246） |
| ONNX 输入 | `obs` float32 `[N,25]`、`obs_history` float32 `[N,125]` |
| ONNX 输出 | `actions` float32 `[N,6]`（**高斯分布的均值，推理是确定性的**） |
| 算子 | 7×Gemm + 5×Elu + 1×Concat（单片机上就是一个 3 层 MLP + 一个 4 层 MLP） |
| 预处理 | **没有任何观测归一化/标准化**，观测按下面表格缩放后直接进网络 |
| 后处理 | 动作裁剪到 ±100（实际不会触发，策略输出量级 ±5 以内） |

## 3. 输入一：`obs`（25 维）

顺序严格如下。**下标从 0 开始**，单位已写明，`缩放`列是进入网络前乘的系数。

| 下标 | 名称 | 含义 | 单位 | 缩放 | 实机来源 | 实测范围（前进 1 m/s） |
|---|---|---|---|---|---|---|
| 0–2 | 角速度 | **机体系**三轴角速度 ω | rad/s | ×0.25 | IMU 陀螺（若是世界系需先转到机体系） | ±0.29 |
| 3–5 | 投影重力 | 重力方向在机体系：`Rᵀ·[0,0,-1]` | 无量纲（单位向量） | ×1 | IMU 姿态/四元数 | z ≈ −1.0 |
| 6 | 前进速度指令 | 期望 vx（+前） | m/s | ×2.0 | 手柄 | ±4.0 |
| 7 | 偏航角速度指令 | 期望 ωz（+左转） | rad/s | ×0.25 | 手柄 | ±0.5 |
| 8 | 机身高度指令 | 期望 base_link 离地高度 | m | ×5.0 | 手柄 | 0.55–0.95 |
| 9 | 左髋关节角偏差 | `q_rear_L − q_def` | rad | ×1.0 | 编码器 | ±0.37 |
| 10 | 左**虚拟膝**角偏差 | `q_shank_L − q_def` | rad | ×1.0 | 编码器 + 闭环逆解 | ±0.21 |
| 11 | 右髋关节角偏差 | `q_rear_R − q_def` | rad | ×1.0 | 编码器 | ±0.32 |
| 12 | 右**虚拟膝**角偏差 | `q_shank_R − q_def` | rad | ×1.0 | 编码器 + 闭环逆解 | ±0.20 |
| 13–15 | 左腿角速度 | `[髋, 膝, 轮]` | rad/s | ×0.05 | 编码器前后差分（轮要 ±π 环绕） | 轮可达 ±20 |
| 16–18 | 右腿角速度 | 同上 | rad/s | ×0.05 | 同上 | 同上 |
| 19–24 | 上一步动作 | 上一次网络输出（未缩放） | 无量纲 | ×1.0 | 自己缓存 | ±3.6 |

要点：

* **顺序是"左腿 3 个 + 右腿 3 个"，不是左右交替**。
* 第 9–12 维只放 4 个位置量（髋、膝），**不含车轮角**；第 13–18 维放全部 6 个角速度。
* 观测里**没有线速度**（没有 vx/vy 反馈），所以策略是靠"轮速前馈 + 姿态反馈"跑的：
  轮子的速度指令必须准，编码器换算要对。
* 观测里**没有接触力、没有高度传感器**，高度只作为**指令**输入，机器人不需要测自己的高度。
* 全向量最后裁剪到 ±100（观察值远小于此，实际不触发）。

### 3.1 训练时叠加的观测噪声（移植参考）

训练时 `2·U(−1,1)` 均匀噪声按下列尺度加到观测上（`np.random.uniform(-1,1)` 再乘系数），
单片机**不需要**加噪声，但要知道策略的传感器噪声容忍度就是这些量级，实机噪声别明显超过：

| 下标 | 噪声幅值（加在缩放后的观测上） | 折算到物理量 |
|---|---|---|
| 0–2 | ±0.05 | 角速度 ±0.2 rad/s |
| 3–5 | ±0.05 | 姿态约 ±3° |
| 6–8 | 0 | — |
| 9–12 | ±0.02 | 关节角 ±0.02 rad（1.1°） |
| 13–18 | ±0.075 | 角速度 ±1.5 rad/s |
| 19–24 | 0 | — |

## 4. 输入二：`obs_history`（125 维 = 5 帧 × 25）

* 布局：`[第1帧(最旧) 25 个, 第2帧, 第3帧, 第4帧, 第5帧(最新=当前 obs)]`
  —— **最新的在末尾**，这也是 ONNX 里拼 125 维的顺序。
* 更新：每个控制周期固定一次（100 Hz），把整段往前挪 25 维，把当前 obs 放到末尾。
* 时间窗：5 × 10 ms = **50 ms**。
* **复位/上电时**：用当前那一帧 obs 重复填满 5 帧（和训练 reset 的行为一致），
  不要填零。
* 注意：进历史的是**加了噪声的** obs（实机上就是你自己算出来的那 25 个数），
  网络看到的当前帧和历史的最后一帧是同一份数据。

## 5. 输出：`actions`（6 维）

网络输出 6 个数，**就是各关节的目标量**（髋/膝是位置偏置，轮是转速），顺序和输入一致：

| 下标 | 关节 | 含义 | 单位 | 换算 |
|---|---|---|---|---|
| 0 | 左髋（大腿 `Left_rear_joint`） | 位置偏置 | rad | `q_tgt = q_def + 0.5·a[0]` |
| 1 | 左**虚拟膝**（`Left_rear_child1_joint`） | 位置偏置 | rad | `q_tgt = q_def + 0.5·a[1]` |
| 2 | 左轮（`Left_Wheel_joint`） | 转速指令 | rad/s | `ω_ref = 10·a[2]` |
| 3 | 右髋 | 位置偏置 | rad | `q_tgt = q_def + 0.5·a[3]` |
| 4 | 右**虚拟膝** | 位置偏置 | rad | `q_tgt = q_def + 0.5·a[4]` |
| 5 | 右轮 | 转速指令 | rad/s | `ω_ref = 10·a[5]` |

### 5.1 关节伺服（PD）

```
髋/膝:  τ = kp·(q_def + 0.5·a − q)  +  kd·(0 − q̇)
轮  :  τ = kd_w·(10·a − ω)                      (kp_w = 0)

kp   = [40, 40, 0, 40, 40, 0]        # N·m/rad
kd   = [ 2,  2, 0.2, 2,  2, 0.2]     # N·m·s/rad
限幅 = [40, 40, 20, 40, 40, 20]      # N·m，分别对应 髋/膝/轮
```

* 默认角 `q_def`（rad，顺序同上）：`[-0.274884, +0.517721, 0, +0.274883, -0.517722, 0]`
* 这个默认角是**离散化前的"重力静平衡点"**（PD 零误差点），不是几何零位，必须原样使用。
* 电机折算：`电流 = τ / (Kt · 减速比 · 效率)`，这一步按你们驱动器参数表算。
* 训练时的域随机化：`kp/kd` ×[0.8,1.2]、电机力矩 ×[0.8,1.1]、摩擦 ×[0.6,1.4]、
  整机加质量 [−1,+2] kg、惯量 ×[0.9,1.1]、质心 ±2 cm、默认角 ±0.03 rad、
  恢复系数 [0.6,1.0]、**动作延迟 0~10 ms 随机**。
* **电机响应建模**（第二版特意加的）：策略训练时 PD 输出的力矩不是立刻生效，而是
  1) 先经过 0~10 ms 的**动作延迟**（按 5 ms 仿真子步取整），2) 再经过一阶**执行器滞后**
  `τ ← τ_prev + (τ_cmd − τ_prev)·dt/τ_actuator`，`τ_actuator = 15 ms`。
  换句话说：真机的电流环/CAN 延迟只要在 10 ms 量级、力矩上升时间在 15 ms 量级，
  策略就是按这个假设训出来的，不需要额外补偿。
  想复现这个"慢电机"条件做离线测试（sim2sim）：

  ```bash
  python onnx_mj_v11.py --onnx <策略>.onnx --cmd-lin-vel 1.5 \
      --delay-steps 1 --actuator-tau 0.015 --duration 8 --no-viewer
  ```

  （`--delay-steps 1` = 延迟一个策略周期 10 ms；`--actuator-tau` 单位秒，0 = 理想力矩源。）

## 6. 关节顺序与正方向（最容易错的地方）

**训练模型/策略口径**的 6 个关节 = **每一侧的"大腿 → 虚拟膝 → 轮"**，即：

```
[0] 左大腿(髋后)  [1] 左虚拟膝  [2] 左轮  [3] 右大腿(髋后)  [4] 右虚拟膝  [5] 右轮
```

正方向定义（base 系：x 前 / y 左 / z 上）：

| 关节 | 世界轴方向 | 正方向的物理效果 |
|---|---|---|
| 左腿 全部 3 个 | **+y**（指向机器人左侧） | 右手定则绕 +y |
| 右腿 全部 3 个 | **−y** | 右手定则绕 −y（左右镜像） |

单侧腿的平面角关系（标定结果，`q` 都是上面口径的关节角）：

```
theta1 = a1 + sgn·q_rear      a1 = 179.870°, sgn = −1(左) / +1(右)
theta2 = a2 + sgn·q_shank     a2 = −212.108°, sgn 同上
theta1 是"髋→膝"方向相对 +x 的角（逆时针为正，在 x–z 平面内量）
theta2 是"膝→轮心"方向相对大腿的角
```

**三步校符号（上电第一次一定要做）**：

1. 让机器人吊起来，把大腿摆到**水平朝后**（膝在髋正后方）：此时 `q_rear` 应 ≈ 0。
2. **左腿** `q_rear` 增大 → 大腿**向上抬**；**右腿** `q_rear` 增大 → 大腿**向下压**。
   （左右腿是镜像，所以同一套动作左右数值符号相反，这与 `q_def` 里 ±0.27 的镜像一致。）
3. **左腿** `q_shank` 增大 → 腿**变长**（轮心离髋更远）；**右腿** `q_shank` 增大 → 腿**变短**。

   （标定实测：左腿 `q_shank = +0.1` 时 L0 由 0.135 → 0.157 m；右腿 `q_shank = +0.1`
   时 L0 由 0.135 → 0.114 m。）

如果 1/2/3 中任何一条不对，先把对应关节的编码器读数取反（这是唯一正确的修法），
**不要去改网络输入的顺序或符号**。

## 7. 真机闭链映射（策略 ↔ 硬件）

策略是在**串联腿**（大腿→膝→轮）上训的，真机是**闭链**：电机在"后髋(大腿)"和
"前髋(曲柄)"上，膝是被两条销轴带出来的。所以要有两组换算：

### 7.1 状态：真机 (前髋, 后髋) → 策略的 (髋, 虚拟膝)

```
输入: q_front(左前髋/曲柄), q_rear(左后髋/大腿)     ← 编码器
输出: q_shank = 虚拟膝角                             ← 喂给 obs[10]
      q̇_shank = d_rear·q̇_rear + d_front·q̇_front     ← 喂给 obs[14]
其中 d_rear = ∂q_shank/∂q_rear, d_front = ∂q_shank/∂q_front（雅可比，第 7.3 节）
```

解法是"两条销轴必须重合"的 4 元方程组（未知量：`child1, child2, child3, shank`）：

```
residual = [ (pin1_A − pin1_B)_x, (pin1_A − pin1_B)_z,
             (pin2_A − pin2_B)_x, (pin2_A − pin2_B)_z ]  = 0
```

直接照抄 `../tools/leg_kinematics_ref.py` 的 `LegRef.solve()`（纯 numpy，20 行牛顿迭代，
每次求解 μs 级；用上一拍的解当种子，一般 1–2 次迭代收敛）。
**注意**：这个机构平面上有 1–3 个装配解（镜像分支），必须靠连续性锁死物理分支——
所以每次求解都要把上一拍的解当种子，并且**限步长**（脚本里 `max_step=0.35` rad）。

### 7.2 力矩：策略的虚拟 (髋, 膝) → 真机 (后髋, 前髋)

由虚功原理（δq_knee = d_rear·δq_rear + d_front·δq_front）：

```
τ_后髋(大腿) = τ_hip_虚拟  +  τ_knee_虚拟 · d_rear
τ_前髋(曲柄) =                τ_knee_虚拟 · d_front
τ_轮        = τ_轮_虚拟                      （直通）
```

### 7.3 雅可比典型值（左腿，随腿长变化，可离线查表）

| 姿态 | q_rear | q_front | q_shank | d_rear | d_front |
|---|---|---|---|---|---|
| 站立 L0 = 0.205 m | −0.2749 | +0.2726 | +0.3299 | −0.697 | +0.697 |
| 蹲 L0 = 0.170 m | −0.1479 | +0.1456 | +0.1634 | −0.612 | +0.612 |
| 伸 L0 = 0.245 m | −0.4096 | +0.4073 | +0.5275 | −0.766 | +0.766 |

可以看到 `d_front = −d_rear`（该机构在站姿附近就是"膝角 ≈ 常数 + (q_rear − q_front) 的函数"），
但**不要**把这个当成恒等式写死，直接用 `LegRef.jacobian()` 算（中心差分，两次额外求解）。
左右腿的数值**相同**（关节符号镜像与几何镜像互相抵消），所以力矩映射公式左右可以共用一套。

## 9. 单片机实现清单

1. **时钟**：控制环 100 Hz（10 ms），固定周期（最好用定时器中断/看门狗驱动）。
   网络前向 + 运动学求解必须在 10 ms 内完成；估计耗时：网络约 8 万 MAC
   （STM32H7 级别 < 1 ms，M4 加 CMSIS-NN 几毫秒），运动学牛顿迭代 μs 级。
2. **数据类型**：全 float32（或定点 Q15，注意 ELU 的指数部分需要额外范围）。
   权重 38.8 k 个 → fp32 152 KB，int8 38 KB（含量化参数）。
3. **网络写法**：`h = ELU(W·x + b)`，逐层手写即可：
   * encoder：`125→128→64→3`
   * actor：`28→128→64→32→6`（输入是 `obs` 25 维和 latent 3 维拼起来的 28 维）
   * 最后不要加激活，输出就是动作均值。
4. **状态量**：6 个关节角（编码器）、6 个角速度（差分 + ±π 环绕）、
   IMU 角速度与姿态、3 个指令、上一拍动作（缓存）。
5. **启动流程**：
   a) 上电先让腿伺服到默认角 `q_def`（或把机器人吊起/扶住）；
   b) 用当前 obs 复制 5 份填满 history；
   c) 开始 100 Hz 控制环，指令从 0 开始斜坡给。
6. **安全**：
   * 力矩硬限幅（髋/膝 ±40 N·m、轮 ±20 N·m，与训练一致；真机再按电机能力取小值）；
   * 倾角保护：`|投影重力_z| < 0.5`（倾角 > 60°）持续若干毫秒 → 卸力；
   * 关节角越限 → 卸力；通信/IMU 超时 → 卸力；
   * 闭环逆解残差超阈值（销没闭上）→ 说明编码器或几何异常，卸力报警。

## 10. 怎么验证你的移植（逐维对照）

1. 生成参考数据（本机跑，CPU 就行）：

   ```bash
   cd rl_chassis/rl/mujoco
   python onnx_mj_v11.py --onnx v11_plane_3000.onnx \
       --cmd-lin-vel 1.0 --duration 2 --no-viewer --dump ref.csv
   ```

   `ref.csv` 每 10 ms 一行：`t, obs0..24, act0..5, q0..5, qd0..5, tau0..5`
   （`q/qd` 是策略口径的 6 个关节，`tau` 是**映射后的真机力矩**）。

2. **纯软件对齐**（不用硬件）：把 `ref.csv` 的 `obs0..24` 按行喂进你单片机上的网络，
   逐行比对输出的 `act0..5`；再用手写的闭链逆解复算 `q1/q4`（虚拟膝）和
   `d_rear/d_front`。要求：动作误差 < 1e-3，虚拟膝角 < 1e-4 rad。

3. **台架对齐**（吊起、轮子离地）：给 `cmd = 0`，检查 6 个关节能不能稳住；
   给 `cmd_h` 从 0.15 走到 0.18，看腿是否同步伸长；给 `cmd_vx = +0.5`，
   看轮子转向是否为"往前滚"，左右轮符号是否相反。

4. **落地**：从 `cmd_vx = 0` 起，逐步给速度；先验证站立，再验证 +/- 速度与转向。

## 11. 已知偏差（移植时留意）

### 11.0 高度指令的跟踪精度（已对齐）

`v11_terrain_tall` 在两侧仿真里的高度跟踪几乎一致（误差 ≤1 cm）：

| 高度指令 | Isaac | MuJoCo |
|---|---|---|
| 0.15 m | 0.1528 | 0.1512 |
| 0.21 m | 0.2102 | 0.2095 |
| 0.24 m | 0.2385 | 0.2391 |
| 0.27 m | 0.2646 | 0.2661 |

（早期版本这里曾出现"MuJoCo 封顶在 0.187"的假象，原因是 sim2sim 脚本里的高度指令上下限
还停留在第一版的 `[0.11, 0.19]`，测试用的 0.22~0.27 全被夹到 0.19。`CMD_RANGES` 已改。）

### 11.0b 单级 20 cm 台阶：卡在底盘几何，不是策略

`rl_chassis_v11_step20_scene.xml` 是单级 20 cm 台阶（3 m 深台面）。实测（MuJoCo，闭链模型）：

* 高度指令 0.22 / 0.24 / 0.27 / 0.30，接近速度 0.15 / 0.25 / 0.6 m/s 全试过；
* 机器人能开到台阶前、轮子甚至有一次踩上台面（接触记录 `轮->step×1`），
  但同时出现 `step1 ~ base_link` 接触——**底盘前缘在点头 13~16° 时刮到台阶立面**，
  随后被弹回，反复几次；
* 根因是几何：车长 0.567 m，点头 14° 时前缘下沉 `0.28·sin14° ≈ 6.8 cm`，
  所以底盘离地高度必须比台阶高出一个"点头余量"。按 `L0 = B − h + 0.055` 算，
  跨 20 cm 台阶需要站姿 B ≥ 0.22~0.27 m（越低越不可能，不是策略能补的）。

**结论**：本车的"能上多高"基本由**站姿高度减去点头下沉量**决定，目前 ~15 cm 是稳的，
20 cm 需要站到 0.27 m 以上并且少点头（或改前悬/加底护板）。策略侧已经能做的是：
站姿指令 0.12~0.27 m 全程跟踪 ≤1 cm、纯台阶地形（5~19 cm）在 0.15~0.27 各档高度指令下
15 s / 256 环境 **零摔倒**。

1. 训练模型删掉了前链（曲柄 + 三根连杆 + 两个销）的**质量**，每侧少约 0.20 kg；
   闭环在 MuJoCo 里是**软约束**（`solref 0.002`），实机是刚性销——所以真机的腿部
   动力学比仿真"硬"一点，策略对此不敏感（训练有 20% 的参数随机化）。
2. 策略精度：站姿高度有约 6 mm 稳态偏差、起步瞬间有约 0.1 m/s 的后退过渡，
   属于 3000 轮训练的收敛水平，多训/加跟踪权重可收紧。
3. 当前 ckpt 只在**平地**上训过；复旦部署到台阶地形用的是 trimesh 台阶训练出来的策略，
   要上台阶需要换地形重训（`legged_robot_config.py` 里 `terrain.mesh_type`）。
4. 结论：**正方向符号**（编码器、电机、IMU 三处一致）是唯一必须由你在硬件上确认的东西，
   第 6 节的三步校符号请务必做一遍。
